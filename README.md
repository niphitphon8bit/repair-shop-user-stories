# ซ่อมดี IT Service · แอปจัดการร้านซ่อม

เว็บภาษาไทยสำหรับเจ้าของร้าน พนักงานหน้าร้าน ช่าง และลูกค้า มี Python API + SQLite บันทึกข้อมูลจริง พร้อมหน้าจอที่ใช้บนมือถือได้ ไม่ต้องติดตั้งแพ็กเกจ Python เพิ่ม

## เปิดใช้งาน

ต้องมี **Python 3.12+** รันจากโฟลเดอร์โปรเจกต์:

```bash
python3 -m app.server
```

เปิด **http://127.0.0.1:8000** · หน้าลูกค้า **http://127.0.0.1:8000/track**

ครั้งแรกเซิร์ฟเวอร์แสดงรหัสผ่านสุ่มใน Terminal บัญชีเริ่มต้นทั้ง 5 ใช้รหัสนี้: `owner@somdee.test`, `front@somdee.test`, `boy@somdee.test`, `bank@somdee.test`, `em@somdee.test` เจ้าของร้านตั้งรหัสใหม่แยกแต่ละบัญชีได้ที่ **ตั้งค่าร้าน → บัญชีพนักงาน** หรือกำหนด `SHOP_INITIAL_PASSWORD` ก่อนเปิดฐานข้อมูลใหม่ (ไม่มีผลกับบัญชีเดิม)

### ทดลองด้วยงานตัวอย่าง 9 งาน

```bash
python3 -m app.demo
```

ใช้ฐานข้อมูลแยก `.data/demo.sqlite3` • เวลาเริ่มต้น 11 พ.ย. 2026 12:00 (เวลาไทย) • บัญชีเจ้าของร้าน `owner@somdee.test` • รหัสผ่านเดโม `SomdeeDemo2026!` • ลูกค้าทดลองเลข `SD-TEST-001` กับเบอร์ 4 ตัวท้าย `2201`

เดโมเก็บการแก้ไขไว้ระหว่างเปิดใหม่ รีเซ็ตงานตัวอย่างได้ที่ **ตั้งค่าร้าน → เครื่องมือทดสอบ** ปิดเซิร์ฟเวอร์เดิมก่อนเปิดอีกโหมดที่พอร์ตเดียวกัน

## สิ่งที่ทำได้

- รับเครื่อง: ข้อมูลบังคับ รูป 2–6 รูป ความยินยอม รหัสเครื่อง เลขใบรับอัตโนมัติ พิมพ์ใบรับพร้อม QR และป้ายแปะเครื่อง
- งานช่าง: รับงานตามทักษะ มอบงานใหม่ 9 สถานะ ประวัติผู้เปลี่ยนและเวลา วันนัดใหม่เมื่อรออะไหล่
- ใบเสนอราคา: R01–R09 และรายการนอกตาราง ฉบับที่ส่งแล้วไม่แก้ย้อนหลัง ยืนยัน/ปฏิเสธทางหน้าลูกค้าหรือโทรศัพท์ กฎเพิ่มราคา 10% งานด่วนและวันหยุด
- ลูกค้า: เช็กเลขใบรับและเบอร์ 4 ตัวท้าย ย่อชื่อ ล็อก 15 นาทีเมื่อผิด 5 ครั้ง โดยไม่ต้องสมัครสมาชิก
- คืนเครื่อง: ค่าตรวจ ค่าด่วน ค่าฝาก ส่วนลด ยอดปิดงาน ตรวจผู้รับแทน รับเงินครบ ออกใบเสร็จเดี่ยวหรือรวมหลายเครื่องที่รับพร้อมกัน ยกเลิกใบเสร็จพร้อมเหตุผล
- ประกัน: ตรวจตามรายการและวันคืน เปิดใบรับเคลมอ้างใบเดิม เคลม ฿0 ไม่ต้องยืนยันซ้ำ ยึดอายุประกันเดิม
- การจัดการ: ค้นหา รายงานรายวัน ตั้งราคา/วันหยุด เปิดและปิดบัญชี รีเซ็ตรหัสผ่าน ข้อความ LINE จำลอง รายการต้องโทร และเตือนงานเลยนัด

## การทดสอบ

```bash
python3 -m unittest discover -s tests -v
npm ci
npx playwright install chromium
npm run test:e2e
```

Unit/API tests ใช้ฐานข้อมูลชั่วคราว ส่วน browser tests ใช้ `.data/browser-test.sqlite3` แยกจากข้อมูลร้าน ครอบคลุมการตรวจสิทธิ์ ความลับของรหัสเครื่อง เลขใบรับพร้อมกัน 10 ใบ วันหมดอายุ ค่าฝาก ราคา การรับเงิน เคลม รวมใบเสร็จ และหน้าจอมือถือ 360 × 800

## ข้อมูลและการตั้งค่า

| ตัวแปร | ค่าเริ่มต้น / การใช้งาน |
|---|---|
| `SHOP_DB` | `.data/shop.sqlite3` |
| `SHOP_HOST` | `127.0.0.1` |
| `PORT` | `8000` |
| `SHOP_INITIAL_PASSWORD` | รหัสสุ่ม แสดงครั้งแรก ใช้เฉพาะสร้างบัญชีเริ่มต้น |
| `SHOP_TEST_MODE` | `1` เปิดการตั้งเวลาทดสอบและรีเซ็ต (สำหรับ owner เท่านั้น) |
| `SHOP_SECURE_COOKIE` | `1` เมื่อให้บริการผ่าน HTTPS |

SQLite ใช้ transaction และ WAL; เก็บเงินเป็นบาทเต็ม ข้อมูลเวลาใช้ `Asia/Bangkok` ระบบตรวจหมดอายุ เตือนงาน และลบรูปที่เกินอายุทุก 30 วินาทีขณะเซิร์ฟเวอร์ทำงาน รวมถึงก่อนอ่าน API

สำรองข้อมูลโดยหยุดเซิร์ฟเวอร์แล้วคัดลอกไฟล์ฐานข้อมูล หรือใช้ SQLite backup API ข้อมูลร้าน รหัสเริ่มต้น และข้อมูลทดสอบไม่ถูกเก็บใน Git

รุ่นนี้ให้บริการในเครื่อง / เครือข่ายร้านผ่าน Python HTTP server หากเปิดภายนอกให้ใช้ HTTPS reverse proxy และตั้ง Secure cookie ฐานข้อมูลมีข้อมูลส่วนบุคคลและรหัสเครื่อง จึงต้องจำกัดสิทธิ์เข้าถึงไฟล์และข้อมูลสำรอง การส่ง LINE เป็น **ข้อความจำลองตามข้อกำหนด** ไม่ได้ส่งออกบัญชี LINE จริง ไม่มีระบบชำระเงินออนไลน์หรือใบกำกับภาษี

โครงสร้างและรายละเอียดกฎ: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md)

## ✍️ สิ่งที่ต้องส่ง: `USER-STORIES.md`

ใช้รูปแบบเดียวกับ `_solution/USER-STORIES.md` ของสบายใจ สปา

1. **ตารางสรุป**: รหัส `US-xx` · เรื่อง · ใครขอ · ความสำคัญ (`Must` / `Should` / `Could`)
2. **แต่ละ story** มี:
   - ประโยค "ในฐานะ … ฉันอยาก … เพื่อ …"
   - **ใครขอ**: อ้าง **เลขบรรทัด** ใน `INTERVIEW.md` หรือ **§** ใน `OWNER-ANSWERS.md`
   - **เกณฑ์ยอมรับ**: ตรวจได้ด้วยตัวเลขหรือข้อความจริง และครอบคลุม **ค่าขอบ** (เช่น วันที่ 7 กับวันที่ 8 · วันที่ 60 กับวันที่ 61)
3. **รหัสที่ต้องใช้**:
   - **K1, K2, …** = เรื่องที่คนในร้านพูดขัดกัน (ระบุว่าใครพูดอะไร บรรทัดไหน)
   - **Q1, Q2, …** = คำถามที่ต้องถามร้าน
   - **⚠️ A-01, A-02, …** = สมมติฐานที่ทีมใช้ระหว่างรอคำตอบ
   - **(ทีมเสนอ)** = ตัวเลขหรือข้อความที่ทีมคิดเอง ร้านยังไม่ได้พูด
4. **ท้ายไฟล์**: ตาราง K / Q / A ทั้งหมด
